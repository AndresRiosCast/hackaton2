# Equipo y revisión

| Rol | Entrega | Revisión independiente |
|---|---|---|
| `contenido-fidelidad` | Fichas con guion/página, contradicciones, preguntas de oro | `qa-seguridad` verifica trazabilidad y riesgo de respuestas engañosas |
| `dev-app-ia` | BM25, abstención, citas, interfaz, APK y futuro runtime local | `qa-seguridad`; interfaz también por `ux-accesibilidad-psicologia` |
| `ux-accesibilidad-psicologia` | Sistema visual, personaje original, accesibilidad y conducta segura | `qa-seguridad` comprueba que la revisión tenga evidencia |
| `qa-seguridad` | Pruebas, red team, privacidad, evaluación integral | La aceptación final corresponde al Orquestador/usuario, no al autor de la función |
| `documentador-devops` | Bitácora, pitch, ficha de una página y preparación Git | Orquestador revisa exactitud; no declara operaciones Git no ejecutadas |

## Reglas comunes
Contenido de ejecución sin red; responder solo con evidencia de fichas validadas; ante incertidumbre o información cambiante, abstenerse y derivar al personal. No guardar datos personales. Revisores no aprueban su propio trabajo. Las misiones permanecen en backlog hasta petición expresa.
